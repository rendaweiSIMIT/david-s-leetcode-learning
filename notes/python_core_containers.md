# Python 核心容器：当前速记

## 字典动态计数

不需要预先知道会出现多少种值。字典可以在遍历过程中动态增加键：

```python
counts[value] = counts.get(value, 0) + 1
```

这里 `get(value, 0)` 表示：键存在时取原计数，否则从零开始。

## 保序去重

只使用集合可以去重，但不能依靠集合迭代得到输入的首次出现顺序。常用组合是：

- `seen` 集合负责判断是否出现过；
- `result` 列表负责保存输出顺序；
- 按输入顺序单次遍历，在第一次遇到元素时同时更新二者。

核心不变量：处理完输入的前 `k` 个元素后，`seen` 包含这些元素中所有不同的值，`result` 按首次出现顺序保存相同的一组值。

## `O(1)` 不代表不花时间

一次集合查询、集合添加或列表追加当然需要机器时间。`O(1)` 表示：在通常的分析模型下，这次操作的耗时不会随着容器已有元素数量 `n` 成比例增长。

- `item in seen`：计算元素的哈希值，根据哈希定位集合内部位置，必要时比较元素；平均 `O(1)`。
- `seen.add(item)`：执行类似的哈希定位，并可能写入新位置；平均 `O(1)`。
- `result.append(item)`：写入列表末尾；摊还 `O(1)`。列表容量不足时，某一次追加会申请更大的内存并搬移引用，但多次追加的平均成本仍为常数级。
- `item in some_list`：通常必须从头逐个比较，最坏需要检查整个列表，因此为 `O(n)`。

实际时间主要消耗在 Python 解释器执行、哈希计算、元素比较、内存读写和偶尔的容器扩容上。算法面试中的复杂度分析关注输入规模增长时，这些操作次数如何增长。

更具体地说，集合或字典会先对键计算哈希值，再由哈希值定位内部数组中的候选槽位，而不是像列表成员查询那样从第一个元素开始逐个扫描。如果两个键定位到相同或冲突的位置，底层仍需要继续探测和比较；因此内部并非绝对“没有循环”，只是正常情况下探测次数的期望值不随元素总数线性增长。

- 集合保存“哪些键存在”。
- 字典保存“键 → 值”；成员判断 `key in some_dict` 判断的是键。
- 单次集合/字典查询与写入：平均/期望 `O(1)`，极端冲突时最坏 `O(n)`。
- 创建包含 `n` 个元素的集合或字典仍需处理这 `n` 个元素，因此为平均 `O(n)`。

因此，保序去重对 `n` 个输入元素只遍历一次；集合查询和添加按平均 `O(1)` 计算，总时间为平均 `O(n)`，额外空间为 `O(n)`。极端哈希冲突下集合操作可能退化，但常规面试结论应明确说“平均/期望 `O(n)`”。
